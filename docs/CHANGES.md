# What changed from the original (`FUDDO.zip`)

The product, the design system, the layout engine, the shape library and the UI are yours and are unchanged in behaviour: a golden test proves the 3D output is byte-identical to the original for 139 inputs. What changed is the backend and everything around it.

## Backend

| Original | Now |
|---|---|
| SQLite file (`node:sqlite`), one server with a persistent disk | Supabase: Postgres, Auth, Storage. Works on serverless and multiple instances |
| Accounts, scrypt hashes, sessions and rate limits hand-built | Supabase Auth for passwords and sessions; the app keeps throttling, policy and cookie handling |
| Access checks in route handlers | Row Level Security and database functions; route checks remain as a fast path |
| Projects as rows of JSON text; uploads and generated images on local disk | `jsonb` with CHECK constraints; images in Supabase Storage |
| Admin actions in one route with manual transactions | `SECURITY DEFINER` functions that check the caller and audit atomically |
| No password recovery | Forgot / reset flow, throttled, non-enumerating, revokes other sessions |

## Defects found in the original, and fixed

1. **A real consultant could not see the 3D view.** The review page called `/api/model`, which required sign-in; it only looked fine when tested while signed in as the chef. There is now a public, read-only model endpoint keyed by the share link, built from the stored spec.
2. **Every view of a project or review link re-rendered the whole spread.** With a paid provider that meant twelve billable images per page load, including for an unauthenticated consultant. Paid images are now generated once, cached by content hash, and public routes cannot trigger a generation.
3. **Owners could reassign a project or choose their own share link.** `PATCH /api/projects/[id]` accepted `ownerId`, `shareId` and `review` from the owner. Now owners can change the dish and spread only, enforced in the database too.
4. **Sign-in throttling could lock the real owner out.** It counted every attempt against the email alone, before the password check. It now counts only failures, per address and account, so a stranger locks out only themselves.
5. **Password policy contradicted itself.** The README said 12–128 characters; the code accepted 6.
6. **`X-Forwarded-For` was trusted unconditionally**, so a client could pick its own rate-limit bucket. It is honoured only when `TRUST_PROXY` is set.
7. **Spec-card "Back to studio" went to the landing page**, not the studio.
8. **`undo`/`redo` ran side effects (a network render) inside React state updaters**, which StrictMode double-invokes. Fixed.
9. **`useSpec` was a plain function named like a hook**, tripping the React 19 lint rules; renamed. The other React 19 lint findings were fixed (mount flags and media queries are now external stores) or explicitly justified where a component genuinely reacts to a prop change. The project now lints with zero errors and zero warnings.
10. **Dish and spec input was unbounded** (colours interpolated into SVG, `notes` sent to a paid prompt, unlimited components and keys). Everything now has explicit bounds.
11. **The upload route trusted the browser's declared MIME type** and accepted HEIC it could not use. It now sniffs the bytes and accepts JPEG/PNG/WebP.
12. **Request bodies were unbounded.** JSON reads are capped.
13. **`response_format: 'b64_json'` in the OpenAI call.** `gpt-image-1` always returns base64 and, to my knowledge, rejects that parameter. I removed it and handle both response shapes. *I could not verify this against the live API (no key), so check it on your first real generation.*

## Studio and 3D rebuild (October 2026)

- **Studio UI** reorganised into numbered steps with a pinned Generate button, one-line component rows, a share bar above the spread, a collapsed cost panel, and a tidier refine toolbar.
- **3D editor** rebuilt around a live scene: no more rebuild-and-flicker on every drag or tweak; drag follows the pointer, rests on the plate and on other pieces, stays inside the rim, snaps, and undoes cleanly. New tools: outliner, position in cm, multi-select, align/distribute/mirror/repeat, solo/lock, saved views, lighting presets, guides.
- **Realism**: ambient occlusion, physical materials, micro-detail, and photographic ingredient textures from a shared library (Gemini, with a free local stand-in).
- **Polish**: turn the 3D view into a photograph of the same arrangement.
- **Local textures**: with no image service, each food is painted in the style of its kind (seared meat, glossy sauce, leaf with veins, root, fruit, and so on) from its name; every ingredient the studio knows resolves to a kind.
- **3D first**: spread cards (studio and review link) are rendered from the 3D scene, and the refine view opens in 3D. The 2D view is still there as a toggle.
- **Sauce brush**: paint sauce free-hand on the plate in 3D or 2D; tapered strokes, three widths, saved with the plating and shown to consultants. Every stroke is its own object, movable, lockable and deletable individually.
- **Admin → Textures**, `npm run textures:seed`, migration `20261002000000_ingredient_textures.sql`.

## Additions

Studio component list redesign; forgot/reset password; the legacy importer (`npm run import:legacy`); per-chef generation allowance; render cache; security headers; `admin:grant` (service key) replacing the SQLite script; LF line endings and `.editorconfig`.

## Food accuracy pass (October 2026)

A fish fillet came out green and a crushed potato a grey rubble. Both were the same kind of fault: a name the tables did not know fell back to a made-up colour, or to the wrong form and surface. `tests/unit/food-profiles.test.ts` now writes down what about 150 foods should look like (the form, the surface and the colour family), and everything it caught was fixed:

- **Forms.** New `heap` shape for small round things (peas, blueberries, olives, grapes, raspberries); they were being built as a heap of pasta. Gnocchi is pillows, scallops are seared rounds (three to a plate), crushed and smashed potatoes are rough discs (three to a plate), broccoli and cauliflower are florets, and a hash brown, shaved parmesan, crispy shallots, lemon zest and goat cheese each have their own.
- **Surfaces.** What a food is made of now decides its texture, ahead of how it is cut: bacon, ham, sausages, meatballs and fish are meat; pastries, pies, wraps and anything fried in batter are bread; roots (every kind of potato, carrot, beetroot, onion, garlic) are roots; cheeses and eggs are smooth; cucumbers and olives are fruit; nori and dolma are leaf.
- **Colours.** 80 foods had no colour in the table and got one made from their spelling (a fish fillet green, ham green, red cabbage green). They are added.
- **`npm run textures:refresh`** repaints the locally painted textures already stored in the library, which would otherwise keep their old picture for good.

## Realism roadmap

Six improvements, in the order they are being done. Before and after pictures of each step are in `docs/calibration/`.

1. **Colour calibration (done).** The filmic tone mapping the 3D view used pulled saturated food towards pastel: a tomato came out salmon and red wine pale mauve, although the colour tables were right. It now uses Khronos Neutral tone mapping, which keeps hue and saturation, with lower exposure and environment light in all four lighting presets. Same four dishes before and after: `docs/calibration/step1-*.jpg`.
2. **A richer scene (done).** The plate no longer floats in a grey void. A chef picks a table (oak, marble, linen, slate, concrete), props beside the plate (cutlery, a napkin), a lighting preset and an optional soft focus; the choice is saved on the plating (`spec.scene`) and the spread cards, the 2D view and the consultant's review all show it. The lighting now reflects a photographer's studio (large softbox, strip light, front card, overhead panel, warm table bounce), which is what puts a window-shaped highlight on glaze and sauce. Before and after: `docs/calibration/step2-*.jpg`.
3. **Surface detail from the textures (done).** A piece's photograph now also drives its relief and its finish: the fine detail left once the photo's soft overall tone is taken out becomes bumps (pits, fibres, crust), and dark areas are rougher while pale, moist ones catch the light. Light now shows through what is thin: leaves and asparagus glow green at the edge facing away from the key light, meat takes a warm red edge, and sauce a lighter, richer rim. All of it is shader-only (`components/scene/look.ts`), so nothing about the model, the saved spec or the tests changes. Before and after: `docs/calibration/step3-*.jpg`. How far this can go is limited by the textures themselves; real food models (step 5) are what will add true form.
4. **Better plates (done).** The round plate, the coupe and the deep bowl now have a glaze: iron specks (sparse on the white plates, heavier on the grey coupe), soft mottling from uneven firing, a slightly warmer, darker pool at the edge, and on the round plate and the bowl a fine blue-grey line near the rim that is also cut in as a groove. The coupe has a level well and one unbroken curve up to a rolled lip, instead of a flat rim. All in `components/scene/look.ts` (`GLAZE`) and `lib/engine/layout/plates.ts`. A seventh plate, the **shallow bowl** (`shallow-bowl`, a 24 cm pasta or risotto bowl: a small flat well, a wall rising to a rolled lip about 60% as deep as the deep bowl, held-liquid sauce, a glaze of its own), is in the plate list; it needed a database migration first (`supabase/migrations/20261012000000_shallow_bowl.sql`) because the database only accepted six plate names. It is a choice in the plate menu and is not one of the twelve starting directions. Picture: `docs/calibration/step9-shallow-bowl.jpg`. Pictures: `docs/calibration/step4-*.jpg`.
5. **Real food meshes (batch 1 of several).** The free Kenney Food Kit (CC0) was tried and set aside: 100 to 300 triangles a model is coarser than what the library already builds. The models are authored in code instead (`lib/engine/gltf/cuts.ts`). Batch 1: a **steak** (thick block, band of fat down one side), a **breast** (chicken, duck: a teardrop, thick shoulder, pointed tail, keel along the back), a **fillet** of fish (a wedge thinning to the tail, with a texture of chevron muscle blocks and pale seams), and **chips** (square-section, uneven lengths, golden fried surface). Each has its own proportions and its own seared crust. Pictures: `docs/calibration/step5-*.jpg`. Batch 2: a **burger patty** (ragged edge, dimpled top, raised rim), a whole **roast bird** (breast, keel, two drumsticks with bone knobs, folded wings) and **roast chunks** of potato or squash. The library is checked against every food the studio offers (`tests/unit/food-profiles.test.ts`): each has a colour of its own, a form (other than the lumpy mound kept for whole potatoes, celeriac, cauliflower and broccoli), and a painted surface. **The Kenney pack was tried a second time and removed.** The studio drew a food with the pack's model wherever it had one, in the pack's flat colours, and the result was not wanted, so the hand-built shapes above are what the 3D view uses again. Nothing from the pack is left in the project.
6. **More natural arrangement (built; to be checked by eye).** Every piece now has a lean (`Elevation.tilt`, turned into a rotation by `orient` in `lib/engine/layout/orient.ts`, used by both the model builder and the live scene). Garnish settles: leaves and sprigs land at their own angle and follow the slope of what they land on, seeds and crumbs lie nearly flat. A steak, breast, fillet or bird set beside a purée, a mash or a mound of grain comes to rest against it, the near edge lifted onto it, but not in a stacked build such as a burger. Sauce is no longer a neat disc: the pool has a lobed edge, two of its three shapes carry a tongue where it ran, it is flatter across the middle, and a pooled sauce throws a few small spots off its edge.

## The weakest foods, and drinks in a glass

Two more passes on what still looked least like food, after the six steps above.

**Shellfish, whole fish, steak, breast.** Prawns, lobster, crab and a whole fish used to be an asparagus spear, a quenelle and a roast, because the shape table had no form for them. They have their own builders now (`lib/engine/gltf/shellfish.ts`): a prawn is a curled body of overlapping segments with a head, two long feelers and a tail fan; a lobster a heavy segmented tail ending in a fan, with two claws for the whole animal (a "lobster tail" is the tail alone); a crab a flat scalloped carapace with eight legs and two claws; a whole fish lies on its side with a forked tail and fins. Four new forms (`prawn`, `lobster`, `crab`, `wholefish`) with their own proportions, 2D drawings and serving phrases, and the names that were already in the table (king prawn, scampi, langoustine, dressed crab, whole sea bass, sardines, whitebait and so on) point at them. A fillet stays a fillet. A steak's fat is a pale band of its own down one side (`FAT_STEAK`), and a breast is plumper, with a bend along its back. Picture: `docs/calibration/step7-after-shellfish.jpg`.

**Drinks.** Cocktails, coffee, milkshakes and smoothies were a flat pool on a plate. A drink is now the glass it comes in (`lib/engine/gltf/glassware.ts`): a new `glass` form, drawn as a thin-walled glass, translucent and glossy, with the liquid in it carrying the drink's name and colour. Four vessels, chosen from the drink's name: a rocks tumbler (old fashioned, negroni), a tall glass (mojito, milkshake, smoothie, anything iced), a stemmed coupe (martini, margarita, spritz, sangria) and a cup with a handle (coffee, hot chocolate, tea). The glass is a child of the liquid, so moving, recolouring or hiding the drink moves both. Crushed ice goes in the glass, and nothing is stacked on top of one (the "tall stack" composition included). The writer emits `alphaMode: BLEND` and `doubleSided` for any material with an alpha under 1, the viewer gives glass its own finish (clear coat, no relief, no shadow, no photograph), and the 2D picture draws a rim ring over the liquid, with the body of the glass showing as the camera comes down. Names that begin with a drink but are not one (hot chocolate fondant, smoothie bowl, mocha cake, prawn cocktail) are kept off the glass form. Tests: `tests/unit/glassware.test.ts`.

**Rice and grains.** A scoop of rice used to be one smooth dome with grain-shaped bumps pressed into it, which read as rice only from a distance. `grainHeap` (`lib/engine/gltf/piles.ts`) now lays several hundred real grains on the dome, each its own small ellipsoid, turned its own way and tilted to follow the slope, over a darker core so the gaps show shadow and not the plate. Three heaps, chosen from the food's name: long slender rice (about 520 grains), small round couscous, quinoa, polenta and lentils (1,300), and fatter, curved beans, peas and corn (420). Each stays under the 65,535 vertices a 16-bit index can address (checked by `tests/unit/grains.test.ts`). Also this round: a glow-and-gloss finish for egg yolk, honey and syrups (`translucentFood` in `components/scene/look.ts`; true transmission was tried and the piece was not drawn in this render pipeline, so it is not used).

## A pizza that looks baked

**The base is a hand-built model.** `public/models/pizza.glb` was built in Blender (`docs/blender/pizza.blend`): 30 cm across, a puffy, uneven crust with blisters and pits, a 0.5 cm deck, and its browning stored as a greyscale vertex colour. It is Draco-compressed (257 KB); the decoder is in `public/draco/`, copied from three.js, and has to be copied again when three is upgraded. The viewer swaps it in for the procedural pizza (`components/scene/authored.ts`), turning the grey browning into gold, brown and leopard-spot char on the way, and the card's "Download 3D model" writes it into the file too. The deck is lower than the old one, so `DECK_LEVEL.pizza` is -0.6 and the procedural pizza's profile follows it.

**What goes on it has been through the oven.** The sauce is spread once, as one fine, matte film to just short of the crust with a darker cooked-down edge (`pizzaSauce`); it used to be four identical pools stacked on top of each other. Cheese that melts (mozzarella, cheddar, gorgonzola and the rest, `MELTS` in `lib/shapes.ts`) is no longer a round slice standing on the sauce: on a pizza it is a thin, lobed pool with browned bubbles and a sheen (`melt`, `Elevation.melted`). Basil and rocket on a pizza are whole leaves, and they rest on top of the cheese. Before and after: `docs/calibration/pizza-before.png`, `pizza-after.png`, `pizza-after-top.png`.
